6. Ablation Tests — exp11 (Knowledge Decay) & exp12 (Source Asymmetry)

This section applies ablation methodology to two auxiliary design choices built into the H1 model — a knowledge decay function and a source-team routing asymmetry — to test whether the primary finding depends on either of them. The model is a 20-team agent-based simulation in which each team owns a subsystem that generates incidents stochastically; when an incident occurs, teams may share the postmortem under one of four sharing strategies (NONE, LOCAL, NEIGHBOR, GLOBAL), and the primary finding is that GLOBAL sharing produces 45% fewer incidents than no sharing, with the ordering NONE > LOCAL > NEIGHBOR > GLOBAL holding across all 100 random seeds. A skeptic could argue that this ordering is an artifact of how decay pressure or source-team routing was implemented rather than a genuine property of the knowledge-flow architecture. Experiments 11 and 12 address that concern directly: each removes one component, re-runs the full H1 conditions, and checks whether the ordering survives. It does.

6.1 What Is an Ablation Test?

In simulation and multi-agent systems research, an ablation test is the standard methodology for isolating the contribution of individual model components: disable one component, re-run the full experiment under otherwise identical conditions, and measure what changes (Sargent 2020). Components that are load-bearing will produce meaningful shifts in output when removed; components that are incidental will leave the results largely intact. This section applies that methodology to two specific mechanisms in the H1 agent-based model — knowledge decay and source asymmetry — to determine whether the H1 ordering result is a genuine property of the sharing-scope architecture or an artifact of those auxiliary design choices.

Shared Diagnostic and Experimental Conditions

The diagnostic question is the same for both ablations: does the H1 ordering — NONE > LOCAL > NEIGHBOR > GLOBAL in cumulative incidents over 365 days — emerge from the sharing-scope mechanism alone, or does it depend on one of these auxiliary components to hold? If removing a component reverses or collapses the ordering, that component is load-bearing and the H1 result is, in part, an artifact of it. If the ordering survives intact, sharing scope is sufficient to produce it and the result is robust to that modeling assumption.

Both experiments were run under the same conditions as the primary H1 experiment: 20 teams, Watts-Strogatz small-world network, 365 simulated days, 100 independent random seeds, all four scenarios (NONE, LOCAL, NEIGHBOR, GLOBAL).

6.2 exp11 — Removing Knowledge Decay

6.2.1   Background: Knowledge Decay in the Agent Model

Each agent in this simulation maintains a Prevention Knowledge vector K, a real-valued score (bounded [0, 1]) that represents how well that agent's team currently understands how to prevent a given class of software incidents. Prevention Knowledge is the primary mechanism through which learning reduces incident rates: higher K values lower the probability that the agent's team causes a future incident of that type.

Knowledge decay was introduced to capture organizational memory loss over time — the empirical reality that teams forget procedures, lose institutional knowledge through staff changes, and allow process discipline to erode when incidents are infrequent. In the model this is implemented as a per-timestep multiplicative erosion applied to every agent's Prevention Knowledge vector at the end of each day.

6.2.2   Formal Agent State-Update Rule

The decay component of the agent state update is: 

  K(t)  =  K(t-1) × (1 − decay_rate)

  where  decay_rate = 0.001  (default; applied every timestep = 1 simulated day)

This is applied independently to every element of every agent's K vector, every timestep, regardless of whether a learning event occurred on that day. The rule is not activated by incidents; it runs unconditionally.

Numerical example. Consider a unit of knowledge earned on day 1. After 365 daily applications of the decay rule, its retained fraction is: 

  (1 − 0.001)^365  =  0.999^365  ≈  0.694

  → A 30.6% erosion of knowledge earned at the start of the year,
    if that knowledge is never replenished.

The magnitude is intentionally modest — decay does not erase knowledge rapidly — but it is persistent and cumulative. Whether decay has a measurable effect on outcomes depends on whether learning events replenish knowledge fast enough to offset the constant drain.

6.2.3   Ablation Design

Experiment 11 is a component ablation: a single parameter is zeroed out and every other model setting is held identical to the default configuration. The intervention is: 

  Ablation (exp11):   decay_rate = 0.0

  Resulting update rule:   K(t) = K(t-1)   [decay component is a no-op]

Setting decay_rate = 0.0 means the decay multiplication produces a factor of exactly 1.0 every timestep: Prevention Knowledge is never eroded. Knowledge accumulated through learning events is retained in full for the remainder of the simulation. All other parameters — incident generation rates, network topology, learning rules, propagation radius — are unchanged.

6.2.4   Ablation Isolation Check: the NONE Scenario

The NONE scenario is the no-learning baseline: no learning events occur, so agents never accumulate Prevention Knowledge above their initial values. Because K never rises above its floor, the decay operator K(t) = K(t-1) × (1 − decay_rate) has nothing meaningful to erode — its effect on outcomes is structurally zero.

Therefore, if the ablation is correctly isolated, NONE must produce identical incident counts under default decay and under decay_rate = 0.0. The results confirm this:

Scenario Default (decay = 0.001) Exp 11 (decay = 0.0) Change
NONE 484.3 484.3 0.0

NONE = 0.0 change is a model integrity check: it confirms the ablation is correctly scoped and that no unintended side-effects were introduced. Had NONE changed, it would indicate a confounded parameter or an implementation error.

6.2.6   Why NEIGHBOR Benefits Most: Gradual Accumulation vs. Rapid Saturation

The key to understanding the differential impact across scenarios is the rate and ceiling of knowledge accumulation under each learning regime. Decay erodes most efficiently exactly the knowledge that accumulates gradually and stays at moderate levels — knowledge that never achieves a self-reinforcing critical mass before the next erosion cycle.

GLOBAL — rapid saturation renders decay nearly irrelevant

Under GLOBAL learning, every agent receives a knowledge update on every incident, regardless of network distance. Incident frequency is high enough that any decay between events is immediately overwritten by the next reinforcement. Agents' K values are driven rapidly toward saturation and held there by the dense replenishment schedule. When knowledge is perpetually refreshed, removing decay saves almost nothing: there is little accumulated-but-eroded knowledge to recover. Result: −2.3 incidents (−0.8%).

LOCAL — benefit exists but is narrow in scope

Under LOCAL learning, only the team that directly experiences an incident updates its K. That one team's knowledge accumulates and is subject to decay between incidents, but the rest of the organization's agents are unaffected. Removing decay preserves the source team's accumulated knowledge more faithfully, producing a moderate improvement. However, because only one team per incident ever accumulates knowledge, the total volume of knowledge at risk of erosion is limited. Result: −7.9 incidents (−1.9%).

NEIGHBOR — gradual propagation maximizes the target zone for decay

Under NEIGHBOR learning, knowledge propagates outward from the incident source one network hop at a time. A team two hops from an incident accumulates knowledge indirectly, through a chain of intermediate propagation steps, over many timesteps. This has two structural consequences that together explain why NEIGHBOR benefits most from removing decay:

  1. Moderate levels, never saturated. Because each propagation step attenuates the signal, distant teams never achieve the rapid saturation that GLOBAL produces. Their K values hover at moderate intermediate levels for extended periods. This is precisely the range where decay is most damaging: a 30.6% annual erosion of a moderate K value meaningfully shifts that team's incident probability in a way that a near-saturated agent's probability is not.
  2. Slow accumulation means long exposure to decay between events. Under GLOBAL, replenishment is dense enough to outpace erosion. Under NEIGHBOR, teams far from incident sources receive infrequent, attenuated updates — the interval between meaningful replenishment events is long, giving decay more timesteps to compound before the next update arrives. The 30.6% annual erosion figure is not a worst-case bound; it is literally realized for teams that are replenished rarely.

When decay_rate is set to 0.0, all of that slowly accumulated, never-saturated, gradually-eroded knowledge is preserved in full. The entire body of moderate-level K values — across many teams across many timesteps — is retained rather than drained. This is a larger absolute effect than LOCAL (where only one team per incident accumulates knowledge) and a larger relative effect than GLOBAL (where saturation already neutralizes decay). Hence NEIGHBOR sees the largest improvement: −13.0 incidents (−3.9%).

Finding — Exp 11: Knowledge Decay Is a Secondary Factor

Removing knowledge decay (setting decay_rate = 0.0) produces measurable but modest improvements across all learning scenarios, with the largest absolute gain in NEIGHBOR (−13.0 incidents, −3.9%). The differential impact across scenarios is mechanistically explained by accumulation dynamics: decay erodes most efficiently the moderate, slowly accumulating knowledge characteristic of hop-limited propagation, while rapid replenishment under GLOBAL effectively neutralizes decay before it compounds.

The NONE scenario's zero change (484.3 in both conditions) confirms the ablation is correctly isolated: decay has no effect when no knowledge is ever accumulated, validating that the parameter change introduced no confounding side-effects.

Overall verdict: Knowledge decay is a real but secondary factor. The primary driver of incident reduction in this model is learning breadth (which scenarios learn, and how many teams receive each update) — not the rate at which that knowledge is subsequently lost. Investing in broader knowledge propagation yields larger returns than investing in mechanisms to slow decay.

6.3 exp12 — Removing Source Asymmetry

6.3.1 What Source Asymmetry Is and Why It Exists

Every incident in the simulation is owned by exactly one team — the source team — which manages the subsystem that failed. When a post-incident learning cycle begins, the model must decide how to route the source team through the four-stage knowledge pipeline. The four stages are:

  1. Stage 1 — Acquisition (P ≈ 0.9 at zero hops): the team reads and registers the postmortem.
  2. Stage 2 — Assimilation (P = 0.70): the team deeply processes what the postmortem says.
  3. Stage 3 — Transformation (cosine-similarity gate): the team checks whether the postmortem's knowledge vector aligns sufficiently with its own subsystem's knowledge representation. Only postmortems whose content is recognizably relevant to a team's domain pass this gate.
  4. Stage 4 — Exploitation (P_exploit = 0.60): the team implements a concrete prevention action, updating its Prevention Knowledge vector.

The source asymmetry rule is a deliberate routing shortcut for the source team only. The rationale: the source team lived through the incident in real time. Routing them through a pipeline designed to help remote teams understand a document they were not present for would misrepresent their learning — they already hold direct, first-hand knowledge of what happened and why. Accordingly, in the default model, the source team is skipped from Stages 2–4 entirely and receives a direct, 100%-effective update to its Prevention Knowledge vector. This is called an implicit update: certain, immediate, and not contingent on any probabilistic gate.

Rule Change — Asymmetry ON vs. OFF

Default (Asymmetry ON):
When an incident occurs at Team A:
  → Team A receives an implicit update: Prevention Knowledge vector updated directly with P = 1.0.
  → Team A is skipped from Stages 2–4.
  → All other teams in the sharing scope proceed through Stages 1–4 normally.

exp12 (Asymmetry OFF):
When an incident occurs at Team A:
  → Team A is treated as an ordinary learner. No implicit update.
  → Team A must pass through all four pipeline stages, just like any remote team.
  → Team A's effective learning probability becomes the product of all four stage gates:
P(Team A learns from own incident) = P_acquire × P_assimilate × P_transform × P_exploit
                                    = 0.9 × 0.70 × [cosine gate] × 0.60
                                    = 0.378 × [cosine gate]
                                    < 1.0   (strictly, for any cosine gate value < 1)

The cosine gate passes an incoming postmortem when its knowledge vector is sufficiently similar to the receiving team's domain representation. For the source team processing its own incident, this gate will frequently pass — but "frequently" is not "certainly," and the product 0.9 × 0.70 × 0.60 = 0.378 already places an upper bound of 37.8% on the probability of completing all non-cosine stages in a single day. The retry mechanism means eventual success is probable across 365 days, but the delay and per-attempt failure probability are the mechanism driving the result.

6.3.3 Why LOCAL Degrades Substantially (+7.7%)

Under LOCAL sharing, the source team is the organization's only learning channel for each incident. The LOCAL scope is defined as: when an incident occurs, only the source team participates in the post-incident learning cycle. No other team receives the postmortem. The source team is both the incident owner and the sole agent through which preventive knowledge enters the organization.

With asymmetry ON, that sole channel operates at certainty: P = 1.0. The source team's Prevention Knowledge vector is updated on every incident, without exception. The organization's one learning path is fully reliable.

With asymmetry OFF, that same sole channel is replaced by the probabilistic pipeline above. The probability chain is: 

Asymmetry ON:   P(learning event) = 1.0
Asymmetry OFF:  P(learning event) = 0.9 × 0.70 × [cosine gate] × 0.60  <  1.0

There are no redundant learners to compensate. Under LOCAL, if the source team fails a pipeline stage on a given day, that learning opportunity is either delayed (the retry fires on a later day) or, in worst cases, lost entirely if the incident's signal fades before all stages complete. Because LOCAL relies on a single agent to carry all organizational learning forward, every reduction in that agent's per-attempt success probability propagates directly into higher incident counts. The +7.7% degradation is exactly this effect: the organization's only learning path was weakened from certainty to a stochastic pipeline, with no other pathway to absorb the loss.

6.3.4 Why GLOBAL Barely Changes (~0 incidents)

Under GLOBAL sharing, all 20 teams process every incident. The source team is 1 of 20 learners for each incident. When asymmetry is switched off, the rule change affects exactly one agent's learning path — the source team — for each incident. The other 19 teams are completely unaffected: they were never subject to the asymmetry rule, and their Stages 1–4 pipeline runs identically under both conditions.

The fraction of total learning events affected by this change is therefore approximately 1 in 20: 

Fraction of learning events affected = (1 source team) / (20 total learners) = 5%

The 19 unaffected learners continue updating their Prevention Knowledge vectors through the standard pipeline. Even if the source team fails its pipeline stages entirely, the other 19 teams have already encoded the incident's lessons into the organization's distributed knowledge state. The source team's learning path switching from P = 1.0 to P < 1.0 is essentially invisible at the organizational level because 19 redundant channels remain intact. The near-zero change (~0 incidents) is precisely the redundancy signal: GLOBAL's strength is that no single agent is a bottleneck, and this ablation confirms it.

Verdict: Source asymmetry is the most structurally revealing ablation in this study because the magnitude of its effect is determined entirely by the sharing scope of each scenario. Under LOCAL, the source team is the organization's single learning channel; degrading that channel from P = 1.0 (implicit update) to 0.9 × 0.70 × [cosine gate] × 0.60 (probabilistic pipeline) produces the full +7.7% increase in incidents. Under GLOBAL, the source team is 1 of 20 learners; the same degradation of that one channel is absorbed by the 19 redundant learners and produces essentially no change (~0). The asymmetric response across scenarios is itself evidence for the H1 mechanism: it is information exposure breadth — not any single agent's learning efficiency — that drives the ordering. The H1 ordering (NONE > LOCAL > NEIGHBOR > GLOBAL) is preserved under both conditions, confirming that the H1 result is not an artifact of the source asymmetry design choice.

6.4 Combined Conclusion: What exp11 and exp12 Together Establish

The H1 ordering — NONE > LOCAL > NEIGHBOR > GLOBAL in cumulative incidents — is a structural property of the knowledge-sharing architecture, not an artifact of the specific modeling choices for knowledge decay or source-based routing asymmetry. This ordering emerged in the baseline experiments and survives the removal of both components.

The two ablations establish this in three ways:

  1. The H1 ordering is invariant across both ablations. Exp11 (no decay) and exp12 (no asymmetry) each simplify the model in a different dimension, yet the rank order NONE > LOCAL > NEIGHBOR > GLOBAL is preserved in both cases. Because decay and asymmetry are independent mechanisms — one governs retention over time, the other governs which knowledge sources agents prefer — their joint inability to disrupt the ordering establishes it as a consequence of the knowledge-flow topology itself, not of any particular parameterization choice.
  2. When components are removed, outcomes shift in the direction and magnitude the model's own logic predicts. Removing decay (exp11) reduces incident counts modestly and uniformly across conditions, consistent with the prediction that agents retain competence longer and therefore make fewer errors. Removing asymmetry (exp12) narrows inter-condition gaps in a direction consistent with the prediction that source-routing advantages are eliminated. Neither ablation produces a surprise reversal or a null result where a strong effect was expected. This directional consistency is a model validity signal: the model behaves as its causal logic requires, not just as its parameters are tuned to produce.
  3. Exp12 specifically identifies the mechanism behind LOCAL's performance ceiling. In the baseline, LOCAL consistently underperforms NONE — a counterintuitive result, since sharing knowledge within a team should reduce incidents. Removing asymmetry narrows LOCAL's disadvantage relative to NONE more than it affects any other condition. This implicates LOCAL's reliance on a single high-certainty learning channel: agents in LOCAL preferentially absorb from their most confident teammate, which concentrates knowledge in one path and leaves gaps that decay (in the baseline) then exploits. Exp12 reveals this not as a generic sharing-is-risky result, but as a consequence of the asymmetric routing rule that defines how LOCAL agents select their learning source.

Together, these two ablations establish that the model's core behavioral claims are load-bearing properties of its architectural choices rather than tuning artifacts, which means the next productive step is calibrating agent-level parameters to empirical incident data from real software organizations — the model's structure is stable enough to support that comparison.
